# Codex 原生侧边聊天持久化补丁

让补丁启用后新建的**本地侧边聊天**使用 Codex 原生持久线程，并通过原侧边面板恢复。正文由 Codex 保存；补丁只额外保存主会话关联、标题、账户身份和继承轮次 ID。

完整 Git 仓库位于 `/Users/bytedance/projects/codex-side-chat-patch`，可以直接用 GoLand 打开这个目录。

基础实现位于 `feat/persistent-side-chats` 分支，性能优化位于 `feat/minimal-side-chat-overhead`，永久删除位于 `feat/permanent-side-chat-delete`。当前运行的 `/Applications/ChatGPT.app` 已安装 build 24614 的严格适配补丁并正常启动；固定证书签名、完整性和安装记录校验通过。用户已确认快捷键新建的侧边聊天为空，不显示主会话历史；其余桌面功能仍由用户自行验收。

补丁更新须先为新 build 完成严格适配和签名副本校验，再退出应用、原子安装并正常启动。仅点击原应用图标不会执行补丁升级。

当前补丁支持本机本地会话在 ChatGPT 模式下新建侧边聊天，沿用现有快捷键和入口，不增加按钮；持久化、恢复、命名和永久删除功能一并保留。

## 如何生效

Codex 的本地引擎已经支持持久线程，但原侧边创建走临时模式，而且没有持久标签描述。本补丁同时处理正文保存和面板恢复：

1. 本地侧边仍从主会话原生分叉，把创建参数改为 `ephemeral: false`，使引擎保存正文并持续追加新轮次。
2. 保存侧边线程 ID、来源主会话、账户身份和标题。重开主会话时，原布局或 Side chats 列表据此调用原生恢复接口，打开同一个侧边线程。
3. 面板只展示侧边自己的问答；继承的主会话上下文仍由引擎保留。build 24614 的统一时间线响应式订阅 registry，并同时过滤继承轮次及对应位置元数据。关闭面板表示隐藏，关联不会被删除。
4. **Side chats → ⋯ → 永久删除** 提供确认框，删除原生线程及其子代理聊天，并清理索引和布局。× 继续保留记录。
5. 命名复用原生输入文字清理逻辑。没有初始问题时分配唯一占位名，侧边自己的首次发送成功后更新；继承的主会话轮次不计入首轮判断。相同内容追加 `(2)` 等编号，隐藏记录也参与检查；左侧“最近”条目、侧边标签、Side chats 列表和恢复布局保持同名，后续追问不再改名。手动改名与撤销也同步这些位置。

本机本地会话的创建能力判断增加 ChatGPT 模式例外，菜单、现有快捷键和创建函数共用这一判断。按原有快捷键打开侧边栏后，使用现有入口即可继续添加；上下文继承及保存流程复用上述实现。云端和远程 host 保持原行为。

`codex_side_patch.py` 是补丁管理入口。`stage` 复制完整原应用，在副本的 `app.asar` 中替换十二个渲染端 Rspack chunk 和一个主进程资源，增加两份运行时模块，更新 ASAR 头、plist 和框架中的元数据摘要后重签；`apply` 将已验证的完整副本安装到原应用路径，同时保留完整原包。框架适配保留启用标志、版本和 ASAR 完整性校验。保存、恢复及删除逻辑由应用内部执行。另有独立双击启动入口，在打开原应用前检查并重新应用补丁。

兼容 registry 的固定键只发布已验证的稳定快照。渲染端变更命令使用请求级临时键，主进程落盘确认后通过独立回执返回，并清理命令与回执键，避免原生 KV 的乐观发布把命令 envelope 暴露给 registry 订阅者。

当前 build 的完整原厂回滚包位于 `/Applications/.codex-side-patch-ulqwwtr0/ChatGPT.app`，路径记录在 `~/Library/Application Support/CodexSideChatPatch/installation.json` 的 `backup` 字段。旧版本备份和安装副本已清理；软件更新后不可用旧记录覆盖当前新版本。补丁运行时不需要常驻 Python 进程。

## 使用

在本仓库目录执行。先检查安装状态；这不会退出或修改原应用：

```sh
cd /Users/bytedance/projects/codex-side-chat-patch
python3 -B codex_side_patch.py status
```

需要构造新副本时，源包必须是已验证的原厂应用，可先回滚当前补丁。检查 JS 语法、ASAR 摘要、Electron 完整性信息和完整包签名：

```sh
python3 -B codex_side_patch.py stage --output /tmp/codex-side-stage-check
python3 -B codex_side_patch.py verify /tmp/codex-side-stage-check
```

默认使用 ad-hoc 签名，仅供隔离检查，`apply` 会拒绝安装。输出目录必须是新目录。

准备安装时，使用已有的固定代码签名证书。先查询证书 SHA-1：

```sh
security find-identity -v -p codesigning
```

把下面的证书 SHA-1 替换为查询结果中的 40 位值。工具会核对实际签名叶证书和这个值，而不只是核对记录：

```sh
CODEX_SIDE_SIGNER="填入已有固定证书的40位SHA1"
CODEX_SIDE_STAGE="$HOME/Library/Application Support/CodexSideChatPatch/stages/build-24614-strict"
python3 -B codex_side_patch.py stage --identity "$CODEX_SIDE_SIGNER" --output "$CODEX_SIDE_STAGE"
python3 -B codex_side_patch.py verify "$CODEX_SIDE_STAGE"
```

保存正在进行的工作，手动退出 Codex 后再安装：

```sh
python3 -B codex_side_patch.py apply "$CODEX_SIDE_STAGE"
```

工具拒绝运行中替换。仅对已验证由飞书独立 MCP 进程持有的 `cua_node/bin/node_repl` 做精确所有者豁免，交换前必须核对两边运行时字节完全一致，不终止该进程。安装使用同一文件系统上的完整 `.app` 原子交换，保留包含原始签名、`Info.plist` 和资源的完整原包。重复安装当前补丁会返回 `already-patched`。

启动后，在原主会话创建新的侧边聊天。重开主会话时，已打开的标签走原生布局恢复；关闭的侧边聊天可以从主会话的 **Side chats** 列表重新打开。恢复使用原线程 ID，展示只显示侧边问答，继承的主会话历史仍保留在引擎上下文中。

## 界面变化

继续使用原来的主聊天、侧边聊天面板、标签和 **Side chats** 列表。列表补入已保存但已关闭的侧边，点击后在原侧边面板打开；已保存侧边的空状态文案说明可在重启后恢复。关闭面板表示隐藏，走原生持久标签的关闭逻辑。

已保存本地侧边的列表行增加 **⋯ → 永久删除**。确认框展示标题，默认聚焦“取消”；确认后停止正在生成的回复并删除目标原生线程及其子代理聊天。删除期间禁止重新打开和发送消息。失败保留确认框，结果不明确时保留删除状态；主会话再次打开或连接恢复后继续完成。父会话、其他侧边和工作目录文件保留。

名称由原生主进程串行分配，并随索引一起落盘确认。占位名使用本地化的 `Side chat`、`Side chat 2` 等，内容重名使用 `标题 (2)` 等；编号按同一账户、用户和主会话分配。首次成功发送没有可用文字时保留占位名。旧恢复描述和延迟布局写入不会覆盖新名称，左右/底部面板及已关闭列表同步使用索引中的标题。已有完成问答的历史侧边保留原名，不重新读取正文生成标题。

左侧“最近”中的侧边聊天条目按本地 host、线程 ID 和当前账户/用户读取该侧边自己的完整标题，与右侧标签一一对应。缓存摘要、已加载会话和最终列表行均订阅原生索引。最终列表行使用的 `WRqP.e` 在全部七份 Rspack 副本中优先读取侧边标题，避免原生非空 `liveTitle`、乐观标题或 catalog 名称覆盖它。首次命名、手动改名、撤销/重做和重启恢复使用同一个标题。手动改名保留原生输入清理和撤销队列，通过主进程更新索引及布局；落盘失败恢复原名，显式改名不会被迟到的首轮回调覆盖。主会话、云端和远程会话继续使用原生命名流程；不批量改写原生线程名称或增加模型/RPC 调用。

菜单使用应用原生弹层组件，通过 Portal 展示到摘要分区外，避免被固定面板的 `overflow-hidden` 裁剪。原生组件处理定位、键盘导航和点击外部关闭；菜单切换到确认框时保留“取消”的默认焦点。

删除意图由主进程串行合并并等待原生 `flushOrThrow` 落盘确认后才发出 RPC。正文删除确认后，标签关闭绕过语音恢复和撤销关闭记录；布局及索引收尾失败保留可重试状态。已移除的线程 ID 阻止旧快照和旧恢复请求重建记录。实现与验证结论见 [永久删除技术方案](Codex侧边聊天永久删除技术方案.md)。

内存关联清理复用新版核心 `Ioto.ux` 关系 API，保存布局使用原生 `Exwq.V1` 清理路由、面板和焦点。已有 `native-deleted` 记录重试时只完成本地收尾，不再次发送删除 RPC。

独立启动器增加一个名为 **Codex Side Chats** 的入口，本机约 924 KiB，负责检查并打开 `/Applications/ChatGPT.app`，不常驻运行。更新后应用补丁会提示“这一版尚未完成桌面验证，可能有问题”；匹配失败会提示本次未应用。通知由 macOS 显示，是否可见取决于系统通知设置；同一版本和结果成功通知后不重复提示。

build 24614 已把渲染层迁移到 Rspack，并新增原生持久 Side Chat 创建/恢复模块。该模块面向携带首轮输入的持久创建；现有菜单仍通过 `AqOV` 先打开空侧边，因此不能直接替换为该路径。补丁改为复用新版原生 descriptor、恢复、面板控制器、关系和存储 API，只保留空侧边持久分叉、历史 registry 兼容、统一时间线展示边界和永久删除事务。旧版跨 Vite asset 的导入/导出别名注入已移除。

以后每次 Codex 更新都必须重新检查原生创建、恢复、发现、命名和删除能力，再决定保留、收缩或移除补丁层；不能只更新版本、哈希或压缩符号。

## 双击自动启动

生成入口本身不安装补丁，也不启动 Codex。使用入口时会自动检查并在匹配时安装；上述官方授权与桌面验收结论仍适用。

```sh
python3 -B codex_side_patch.py create-launcher \
  --identity "$CODEX_SIDE_SIGNER" \
  --output "$HOME/Applications/Codex Side Chats.app"
```

入口记录当前 Python、Node、仓库、证书和原应用的绝对路径。仓库迁移、解释器删除或证书更换后应重新生成入口。已生成的本机入口位于 `/Users/bytedance/Documents/Trae-CN/temp_20261023_01/Codex Side Chats.app`，目标仍为 `/Applications/ChatGPT.app`。此次从终端执行了相同的 `launch` 流程，完成固定证书安装及启动。

也可以从终端运行相同流程：

```sh
python3 -B codex_side_patch.py launch --identity "$CODEX_SIDE_SIGNER"
```

| 启动时的状态 | 行为 |
| --- | --- |
| 原应用已经运行 | 只聚焦；下次手动退出后再从入口启动才会应用 |
| 已安装当前补丁 | 直接打开原应用 |
| 同版本重装 | 验证并复用副本，重新应用后打开 |
| 更新版目标代码及引擎仍匹配 | 从新版原包构造副本、应用、打开，再提示版本尚未完成桌面验证 |
| 更新版目标代码、签名或引擎不匹配 | 保留当前应用、请求打开，并提示本次未应用 |
| 旧补丁实现 | 先准备当前副本，经匹配的完整原包回滚后再应用 |
| 安装中断 | 先自动恢复；存在无法核对的外部修改时停止启动 |
| 同时双击多个入口 | 一个执行，其余返回 `launch-in-progress` |

副本缓存依据版本、原 ASAR、引擎、完整原厂签名指纹、补丁实现和证书生成，安装前再次核对完整原包。每个缓存包含一份完整 `.app`，上述条件变化后会产生新缓存；闲置缓存可删除，需要时从核验后的原厂源包重新生成。签名策略和框架摘要适配也计入实现指纹。即便 ASAR 相同，其他资源更新也不会被旧缓存覆盖。启动请求后会检查主进程连续存活，单纯 `open` 成功不代表启动成功；这仍不能代替窗口和功能验收。日志位于状态目录的 `launch.jsonl`，只记录启动与安装元数据和错误，不读取聊天正文；缓存和备份不自动删除。

## 回滚、重装与更新

手动退出应用后回滚完整原包：

```sh
python3 -B codex_side_patch.py rollback
```

回滚保留会话正文、原生布局和关联索引。原包是否完整呈现补丁创建的侧边，仍需要桌面验收。

安装状态与事务日志默认位于 `~/Library/Application Support/CodexSideChatPatch/`；原包备份保存在安装目录中的 `.codex-side-patch-*` 目录。若事务期间进程异常退出，启动入口会自动尝试恢复；手动恢复使用：

```sh
python3 -B codex_side_patch.py recover
```

恢复只处理尚未提交的事务，依据两侧完整 ASAR 哈希恢复交换前状态；外部改动会使恢复停止写入。不要提前删除状态文件或完整原包备份。

同版本重装且保留用户数据后，使用启动入口即可重新应用。手动命令默认对未知新版本返回 `unknown`；`status`、`stage`、`verify` 和 `apply` 可显式加 `--try-updated-version` 使用同样的兼容检查。这个选项只放宽版本标签和完整原 ASAR 的固定值，不放宽原厂签名、目标代码、锚点或引擎要求。目标代码变化后仍须新增适配，不能把旧版本完整副本装到新版上。

```sh
python3 -B codex_side_patch.py status --try-updated-version
```

回滚使用安装记录中的实际原包哈希和签名，不会把匹配的新版本降级到旧 build。旧实现的手动更新仍需先回滚再构造副本。

```sh
python3 -B codex_side_patch.py watch --interval 30
```

`watch` 按安装路径持续报告状态变化，用于发现更新或重装；它不自动安装补丁或退出应用。自定义安装位置、状态目录时，把 `--app`、`--state-dir` 放在子命令前面，并在后续命令中使用同一组值。

## 性能与资源约束

目标是尽量减小对原应用和系统资源的影响。补丁没有新增常驻进程、定时器、扫描线程或自动后台采集；原生 KV 使用内存快照，普通读取不触发磁盘 I/O。RPC 日志保留完整输入、输出及错误，仅发生在相关创建、边界读取、恢复和取消调用，不逐 token 输出。

| 环节 | 确定开销与处理 |
| --- | --- |
| 原图标启动 | 不运行 Python 安装器或全包预检；新增模块加载和侧边索引元数据仍有小额开销，未做原包/补丁桌面启动 A/B |
| 自动入口启动 | 打开前完整预检，本机当前热文件缓存下单次约 0.94 秒；主进程的 2 秒健康观察发生在 open 之后，不阻塞已出现的窗口 |
| 首次安装/重新适配 | 完整复制、校验和重签有一次性明显成本，不属于每次聊天或持续后台操作 |
| 最近列表与显示 | 优化版按原生替换快照弱引用缓存校验，继承 ID 集合最多保留 4 组且总计不超过 20,000 个 ID；超限只禁用缓存，不裁剪上下文 |
| 主会话侧边发现 | 按账户、用户、主会话分组缓存元数据引用；新快照重建，旧快照可回收，不复制正文 |
| 创建/关闭/恢复 | 未变化的关系不重复写；实际写入仍提交完整元数据索引，创建额外读取继承 ID，正文由原引擎写盘 |
| 名称同步 | 创建、首次成功发送和手动改名时分配名称；不调用模型、不增加 RPC。左侧条目按 UUID 直接查询，弱引用缓存未变标题的任务投影；面板仅订阅原生索引变更，关闭即释放；完成命名后不再遍历轮次，布局保存只检查该布局已有路由 |

2026-10-26 对已安装基础版本采样 8.09 秒，应用进程组累计 CPU 0.09 秒，约为一个核心的 1.1%；没有发现补丁常驻进程。这是应用整体活动，无法归因于补丁增量，也不能代替原包/补丁在相同任务下的长期对照。

外部 Node 工作负载实验中，“1000 条保存侧边、每条 1000 个继承 ID”的 200 次分类判断中位数从约 162.10 ms 降为 0.0126 ms。数据来自声明的构造负载，证明热路径改进，不能推断整个桌面应用的加速比例。首次新快照校验仍是线性扫描，超长历史的创建、原生保存、完整 RPC 日志及索引写入仍有实际成本。

安装成功并确认安装记录后，`stages` 中的完整签名副本会被清理；`installation.json` 指向当前唯一保留的完整原厂回滚包。清理历史数据时必须保留该原厂备份和事务状态。

## 数据与限制

- 第一版处理新建本地侧边；云端和远程 host 保持原行为。
- 已存在的临时侧边没有原生 rollout；当前协议无法按原 ID 把它转成持久线程。本补丁不迁移旧临时侧边。
- 关联索引使用原生 KV 键 `codex-native-side-chats-v1`，变更命令使用请求级 `codex-native-side-chat-mutation-v1:` 临时键，布局使用原生 `thread-tab-routes-v1:`。索引不存正文。
- 同版本重装保留用户数据时可以重新应用补丁；删除用户数据也会删除正文及索引。
- 修改包需要重新签名。固定本地证书不能继承 OpenAI 的 Team 权限；安装去除厂商绑定的钥匙串、应用组、APS、通信通知与关联域名 entitlement，保留 JIT，并仅为此应用增加 `disable-library-validation` 以兼容没有厂商 Team ID 的本地签名。未修改系统全局安全设置。原厂推送、Universal Links 和相关 Team 功能不能视为已兼容，重新登录及权限仍需验收。
- 补丁接入保存、发现、恢复和永久删除，继续使用原侧边上下文说明及原生权限检查。

## 文件

- `patchkit/profile.py`：精确版本适配与局部资源替换。
- `hooks/`：本地持久创建、原生恢复及摘要列表信号适配。
- `runtime/persistence.mjs`：原生 KV 索引、展示边界、账户检查与完整 RPC JSON 日志。
- `patchkit/archive.py`：ASAR 读取、摘要验证和重建。
- `patchkit/integrity.py`：保留完整性校验的 ARM64 框架元数据摘要适配。
- `patchkit/manager.py`：副本生成、签名核对、安装、回滚、中断恢复与状态监测。
- `patchkit/launcher.py`：独立入口生成、启动前检查与重新应用、完整原包缓存及版本通知。
- `tests/`：合成行为检查和可独立运行的真实协议验证。
